# Ежедневник: версия для ПК (Windows)

Рабочие исходники версии для компьютера. Телефонная версия — в соседней папке `../dayplanner-android`. Ядро и стили общие, интерфейс отличается платформенными настройками; правки общей части переносите в обе версии.

**Состояние (0.2.0).** Добавлены иконки/ZIP, вложения, Dropbox, копии, пароль, отмена и настройки списков. Описание и ограничения — в `../../FEATURES_0.2.md`. Windows-версия собирается; 54 теста Rust проходят. Реальная работа трея, автозапуска и напоминаний в этой проверке не тестировалась. Актуальные команды сборки — в `../../README.md`.

## Что в этом архиве

```
dayplanner-pc/

  core/                         ядро (общее с Android)

  app/
    package.json                команды npm: dev, build, icons

```

## Как работают напоминания на ПК

1. При запуске `lib.rs` вызывает `desktop::start`: фоновый поток раз в 3 секунды берёт у ядра `Store::pending(now)` (дела, которые уже наступили и не отмечены).
2. Для каждого нового дела показывается окно `alert.html` одного из трёх видов, по способу напоминания: уведомление (маленькое, правый нижний угол, исчезает через 45 секунд), будильник (по центру, повторяющийся сигнал, пока не выключат, максимум 5 минут), на весь экран.
3. Кнопки окна вызывают `alert_action`: «Выполнено» и «Пропустить» применяются к ядру сразу с настоящим временем нажатия; «Через 10 минут» откладывает (хранится в памяти); «Закрыть» просто убирает окно, дело остаётся в списке как «пора выполнить». Если действие не удалось (например, «нельзя отметить дело, до которого больше суток»), окно остаётся и показывает ошибку.
4. После «Выполнено» и «Пропустить» главное окно получает событие `planner-changed` и перерисовывает список.
5. Работа в фоне: закрытие главного окна прячет его в трей, приложение продолжает работать. Выйти можно через меню значка в трее. Второй запуск показывает уже работающее окно.
6. Автозапуск: переключатель в Настройки → Компьютер. Запуск вместе с Windows идёт с аргументом `--minimized` (сразу в трей).
7. Пропущенное из-за сна компьютера: всё, что наступило между двумя проходами, показывается независимо от давности, не больше 3 окон за проход (остальные следом, каждые 3 секунды). Если приложение работало без перерыва, показывается то, что наступило не раньше 15 минут назад.
8. Звук: системный сигнал Windows (`MessageBeep`), играет Rust, не веб-страница. Собственных звуковых файлов пока нет.

## Сборка на Windows

Нужно: Rust через rustup (с Visual Studio Build Tools, компонент «Разработка классических приложений на C++»), Node.js 20+, WebView2 (в Windows 10/11 уже есть).

```powershell
cargo test -p planner-core      # проверка ядра
cd app
npm install
npm run icons                   # создаёт иконки; без этого сборка не пойдёт и не будет значка в трее
npm run dev                     # запуск для разработки
npm run build                   # установщики и exe
```

Результат `npm run build`: `app\src-tauri\target\release\dayplanner.exe` и установщики в `app\src-tauri\target\release\bundle\` (папки `nsis` и `msi`).

Интерфейс без сборки: откройте `app\ui\index.html` в браузере (демо-режим, `demo.js`).

Сервер рейтинга: `cargo run -p planner-server --release` (порт 8787, данные в `leaderboard.json`; маршруты `/api/register`, `/api/score`, `/api/leaderboard`, `/api/me`, `/health`; для доступа из интернета нужен HTTPS-прокси).

## Как проверить на ПК

1. `npm run dev`, откройте Настройки → Компьютер, нажмите «Проверить уведомление», «Проверить будильник», «Проверить на весь экран». Должны появиться окна, сигнал звучит, кнопки закрывают окно.
2. Создайте напоминание на ближайшую минуту, закройте главное окно (оно уйдёт в трей) и дождитесь окна.
3. Нажмите «Выполнено», откройте приложение из трея: дело отмечено, очки начислены.

## Известные ограничения

* Отложенные напоминания хранятся в памяти: после перезапуска приложения «Через 10 минут» забывается. Всё, что наступило не раньше 15 минут назад, после запуска снова покажется.
* Уведомления Windows (центр уведомлений) не используются: окна рисует само приложение, чтобы работали кнопки.
* Виджетов на ПК нет (возможная замена: маленькое окно «поверх всех» с делами на сегодня).
* Данные хранятся в `%APPDATA%\app.dayplanner.diary\diary.sqlite3`. Синхронизация между телефоном и ПК есть: ntfy, локальная сеть и файл (описание ниже).
* Положение маленького окна рассчитано для панели задач внизу (отступ 60 пикселей).

### Как идут данные

```
интерфейс (app.js)  --invoke('api', {cmd, args, now})-->  app/src-tauri/src/lib.rs
                                                          --> core::api::dispatch
                                                          --> Store (SQLite) + planner
```

* Время `now` интерфейс всегда присылает с часов устройства (`localIso()` в `app.js`): так статусы и будильники не зависят от часового пояса, который знает Rust.
* Все даты и времена локальные, без часового пояса.
* Любое изменение данных интерфейс сопровождает вызовом `syncSoon()`, который через плагин `planner-native` передаёт системе список будильников и данные для виджетов.

### Модель данных (таблицы SQLite)

`categories`, `notes` (заголовок, текст до 20 000 символов, цвет `#RRGGBB`, закрепление, категория; при удалении категории у заметок обнуляется), `reminders` (повтор хранится JSON-строкой), `schedule_entries` (либо `weekday` 1–7, либо `on_date`), `completions` (отметки по срабатываниям: `done` или `skipped`, очки), `unlocked` (полученные достижения), `kv` (настройки).

Настройки (`kv`): `theme` (material, amoled, glass, simple), `accent` (`#RRGGBB`), `mode` (auto, light, dark), `bg`, `bg_intensity` (10–100), `online.server`, `online.room`, `online.nickname`, `online.token` (скрыт от интерфейса).

### Правила логики

* **Статус срабатывания.** Срок `at`, допуск `grace_minutes`. Нет отметки: до срока «впереди», в окне «пора», после окна «не выполнено». Есть отметка: не позже срока плюс допуск «вовремя», иначе «с опозданием».
* **Очки.** Вовремя 10, с опозданием 4, награда за достижение сверху. Нельзя отметить дело, до которого больше суток.
* **Серии.** День хороший, если в нём есть выполненное и нет невыполненного. Дни без дел серию не прерывают.
* **Уровень.** Порог n-го уровня: 50 × (n−1)² очков.
* **Удаление напоминания** не стирает историю и очки.

### Заметки

Ядро: `Note` в `model.rs`, таблица `notes` и CRUD-методы в `store.rs`, команды `notes.*` в `api.rs`. Интерфейс: вкладка «Заметки» в `app.js` с поиском, цветом, закреплением, категорией и автосохранением. Заметки синхронизируются между устройствами; на виджеты не попадают.

### Синхронизация между устройствами

Сервера нет. Три способа передачи, один и тот же формат данных и слияние:

1. **Через интернет (ntfy).** Устройства группы читают и пишут «канал» на публичном ntfy.sh (можно указать свой сервер ntfy). Имя канала и ключ шифрования выводятся из **кода группы** (16 символов), сервис видит только зашифрованные байты. Данные режутся на сообщения до 3000 символов (`to_messages`, `assemble`); ntfy хранит сообщения около 12 часов, поэтому вступивший в группу шлёт `hello`, а остальные в ответ присылают полный снимок. Большие снимки уходят пакетами по 120 записей (до 120 сообщений за раз); полный снимок отправляется при вступлении, при `hello` от другого устройства и раз в 6 часов, остальное время только изменения. У бесплатного ntfy.sh есть суточные лимиты на число сообщений.
2. **Локальная сеть.** Устройства с включённым способом раз в 15 секунд рассылают UDP-маячок (порт 47832) с хэшем кода и портом TCP (47831), находят друг друга и обмениваются полными снимками по TCP, всё зашифровано. Адрес можно ввести вручную (Настройки → Синхронизация → Дополнительно). На Windows при первом включении брандмауэр спросит разрешение на доступ к сети.
3. **Файл.** «Сохранить файл» / «Загрузить файл»: текст (JSON, а в группе зашифрованный кодом, префикс `DPSYNC1:`), который можно передать чем угодно. Слияние не теряет правки.

**Как устроено слияние.** У каждой записи (категория, напоминание, занятие, заметка, отметка выполнения) есть постоянный `uid` и время изменения `modified` (миллисекунды). Они лежат в таблице `sync_meta` (вид, локальный ключ, uid, время, признак удаления), а не в самих таблицах: `store.rs` вызывает `touch` и `mark_deleted` при каждой записи и удалении. При слиянии для каждой записи побеждает версия с большим `modified`; удаление хранится как запись-«надгробие» и тоже подчиняется этому правилу, поэтому более свежая правка воскрешает удалённое. Числовые id на устройствах разные: ссылки между записями при передаче заменяются на `uid`. Отметка выполнения имеет uid `«uid напоминания|время срабатывания»`. Номера удалённых записей повторно не выдаются. Стандартные категории имеют общие uid (`seed-*`) и не удваиваются. Достижения объединяются (берётся раннее время получения).

Ограничения: побеждает запись с более поздним временем на часах устройств, поэтому часы должны идти примерно верно; настройки оформления и данные рейтинга между устройствами не синхронизируются; фоновая синхронизация работает, пока приложение запущено (на ПК в том числе в трее, на телефоне пока открыто). Вход через Google и Bluetooth пока не сделаны.
